Qwen2.5-Omni audio path in Applications/CausalLM (verified vs HF fp32, 2026-06-12):

- **Encoder** (`models/qwen25_omni/qwen25_omni_audio_encoder.*`): Omni's audio attention is strictly windowed per 200-mel-frame chunk with positions restarting at 0, so a fixed per-chunk graph run repeatedly is mathematically identical to HF — no attention-mask support needed in mha_core. Tail chunks: zero-pad mel, restrict attention rows via `incremental_inference(0, L1)`; mel frame count must be EVEN (avoids a conv2 boundary mismatch on odd tails). mha_core needs `cache_index=0` reset per chunk (forEachLayer), and `rope_theta=0` disables RoPE (`use_rope = theta > 0`).
- **Two-graph trick**: from/to row-slicing is global per inference call, so a pooling layer that halves rows mid-graph breaks slicing. AvgPool runs host-side; ln_post+proj are a second tiny compiled model with its own .bin.
- **Injection** (`layers/embedding_injection.*`): 3-input layer (embedding out, input0 ids, "aud_embd" side input); rows where id==151646 are copied from the side input at the same global position == HF masked_scatter. Host pre-tokenizes the prompt, scatters encoder outputs at placeholder positions; `CausalLM::buildInferenceInputs`/`appendExtraInputs` (refactored virtual) feeds extra named inputs name-sorted after input0.
- **Decoder unchanged**: text+audio uses plain sequential positions in HF too (no M-RoPE divergence); the audio chat model (`Qwen25OmniAudioChat`) loads the SAME decoder .bin as the text model.
- C++ wav→mel front-end implemented (`whisper_mel.cpp`, WhisperFeatureExtractor port, verified max diff 2.6e-5 + wav E2E); `.wav` goes straight into `audio:file.wav ...`. Audio encoder Q4_0 quantization done (2423→360 MiB, fully-quantized voice chat matches FP32).

**Vision (added 2026-06-13):** `Qwen25OmniVisionEncoder` (`qwen25_omni_vision_encoder.*`) = Qwen2.5-VL ViT (patch_embed Conv3d-as-linear, 32 blocks: RMSNorm + separate q/k/v+bias + 2D-RoPE + full mha_core + SwiGLU, then 2x2 patch merger). Custom `layers/vision_rope.*` applies 2D-RoPE (h/w split, head_dim/2 freqs) to q/k for a fixed grid (computed in finalize, no baked weights) — mha_core runs with rope_theta=0. Same two-graph trick as audio: merger's 2x2 reshape changes row count so ln_q ends the main graph and reshape+MLP run as a head graph. **Scope: single-window images only** (≤8x8 patches / 112x112px → 4x4 merged == one window, so windowed==full attention, window_index identity). Verified vs HF fp32: cosine = 1.000000. Windowed attention for any image size is DONE (2026-06-13): custom `layers/vision_attention.*` replaces mha_core in the tower — masks each token to its window (block-diagonal) WITHOUT reordering patches (attention is permutation-invariant; token a attends b iff same window-id, derived from grid at finalize), full-attention layers [7,15,23,31] attend all. Exact FP32 (no KV cache). 2D-RoPE stays in original order. Verified vs HF: 112px (1 window) and 224px (4 windows) both cosine 1.0; end-to-end 224px image chat → "red, green, blue" matches HF. Encoder still compiles per fixed grid (convert per image size, e.g. --grid_h 16).

**Video encoder (added 2026-06-13):** vision_rope + vision_attention generalized with grid_t. Attention never crosses temporal frames (HF cu_seqlens are per-frame even for full-attention layers) → vision_attention window-id = (full: frame; windowed: frame*win_per_frame + spatial_window); 2D-RoPE spatial positions repeat per frame. Converter `--grid_t N`. Verified vs HF: 2-frame 8x8 (grid_t=2) cosine 1.0; images (grid_t=1) unregressed. **Video CHAT DONE (2026-06-13):** `Qwen25OmniVisionCausalLM` handles `video:` prefix — vision token positions get temporal t_index = frame * video_second_per_grid * position_id_per_seconds(25), video_token_index 151656. embedding_injection generalized to a set of token_ids (image,video both matched). Verified vs HF thinker (pixel_values_videos path): 2-frame RGB-stripe video → "red, green, blue" identical. **Critical token fix:** the real vision delimiters are `<|vision_bos|>`(151652)/`<|vision_eos|>`(151653) — "<|vision_start|>"/"<|vision_end|>" tokenize to 6 JUNK tokens each, which broke HF's get_rope_index vision-block detection (the earlier image-chat result matched only because both sides used the junk strings; now fixed in run() + tests). All modalities-in → text-out (text/audio/image/video) now match HF. Remaining: speech OUTPUT (Talker+Token2Wav), use_audio_in_video interleaving.

**Image chat / M-RoPE (added 2026-06-13):** `Qwen25OmniVisionChat` (`qwen25_omni_vision_causallm.*`) wires the vision encoder into the decoder. M-RoPE via custom `layers/mrope_apply.*`: host computes rotary cos/sin from 3D t/h/w positions (port of HF get_rope_index single-image branch) + mrope_section [16,24,24]*2→t,h,w,t,h,w; the layer applies cos/sin to q,k and **mha_core runs rope_theta=0** (else-branch caches the already-rotated key → core untouched, zero risk to other models). embedding_injection reuses the audio path. Verified vs HF fp32 greedy: text path reproduces "Paris"; RGB-stripes image → both "red, green, blue" (noise image diverges on near-tie first token = numeric, not a bug).

**CRITICAL gotcha — graph input order:** `incremental_inference` maps the input float* vector POSITIONALLY to `getInputDimension()`/`input_list` order, which is the graph's CREATION order (input0, then side inputs in creation order, then name-sorted KV caches) — NOT the name-sort the base `CausalLM::buildInferenceInputs` assumes. Adding side inputs (img_embd, mrope_cos, mrope_sin) requires overriding `buildInferenceInputs` to match: input0, img_embd, mrope_cos, mrope_sin, then sorted caches. Dump with a temporary `model->getInputDimension()` print to ground-truth the order (dims distinguish each input). Also: a chat model dir with `tokenizer_config.json` makes main.cpp apply the chat template to the raw arg, mangling the "image:"/"audio:" prefix — omit that file for these models.
